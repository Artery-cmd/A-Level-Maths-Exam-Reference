Component 01 checklist

CPU Architecture

  • FDE cycle: Fetch (PC→MAR, memory→MDR, MDR→CIR, PC++) · Decode · Execute
  • Registers: PC, ACC, MAR, MDR, CIR — know the role of each
  • Buses: data (transfers data), address (specifies location), control (sends signals)
  • Performance factors: clock speed, number of cores, cache size, pipelining
  • Von Neumann: shared memory for data and instructions. Harvard: separate
  • RISC vs CISC: RISC — simple instructions, more registers. CISC — complex instructions, fewer registers
  • Interrupts: ISR saves context, handles interrupt, restores context

Memory & Storage

  • RAM: volatile, random access, main memory. ROM: non-volatile, read only
  • Cache: faster than RAM, closer to CPU. L1 > L2 > L3 in speed, smaller in size
  • Virtual memory: uses HDD/SSD as overflow RAM. Slower — causes thrashing
  • Paging: fixed-size blocks. Segmentation: variable-size logical blocks
  • Secondary storage: HDD (magnetic, moving parts), SSD (flash, faster), optical
  • Secondary storage trade-offs: speed vs capacity vs cost vs durability

Operating Systems & Software

  • OS roles: process management, memory management, I/O management, file management, security
  • Scheduling algorithms: FCFS, Round Robin, SJF, multi-level feedback queues
  • Translators: compiler (whole program at once), interpreter (line by line), assembler (assembly → machine code)
  • Linker: combines object files. Loader: loads into memory for execution
  • High-level vs low-level: HLL portable, easier. LLL fast, hardware-specific
  • Bytecode / JIT compilation: compiled to intermediate code, interpreted at runtime (Java)

Networking

  • TCP/IP stack: Application · Transport · Network · Link (4 layers)
  • TCP: reliable, ordered, connection-oriented. UDP: fast, no guarantee, connectionless
  • Packet switching: data split into packets, routed independently, reassembled
  • IP addressing: IPv4 (32-bit), IPv6 (128-bit). Subnet mask separates network/host
  • DNS: resolves domain names to IP addresses
  • Network security: firewall, encryption, authentication, MAC address filtering
  • Topologies: star (central switch), mesh (every device connected), bus (shared cable)

Databases

  • Relational DB: tables linked by primary and foreign keys
  • Normalisation: 1NF (atomic values), 2NF (no partial dependencies), 3NF (no transitive dependencies)
  • SQL: SELECT, FROM, WHERE, ORDER BY, GROUP BY, JOIN, INSERT, UPDATE, DELETE
  • ACID properties: Atomicity, Consistency, Isolation, Durability
  • Transactions: all-or-nothing. Commit saves, rollback reverts

Legal, Moral & Ethical

  • Computer Misuse Act 1990: unauthorised access, modification of data, DDOS
  • Data Protection Act / GDPR 2018: 6 principles — lawful, fair, transparent, limited, accurate, secure
  • Copyright Designs & Patents Act 1988: protects software/creative works
  • Regulation of Investigatory Powers Act 2000: lawful interception of comms
  • Ethical issues: AI bias, digital divide, environmental impact, surveillance, automation
Component 02 checklist

Big O & Complexity

  • O(1) constant · O(log n) logarithmic · O(n) linear · O(n log n) · O(n²) quadratic · O(2ⁿ) exponential
  • Bubble sort: O(n²) worst/avg, O(n) best. Insertion: O(n²) worst, O(n) best
  • Merge sort: O(n log n) all cases. Quick sort: O(n log n) avg, O(n²) worst
  • Binary search: O(log n). Linear search: O(n)
  • Dijkstra's: O((V+E) log V) with priority queue
  • Tractable: polynomial time. Intractable: no known polynomial solution (e.g. travelling salesman)

Standard Algorithms

  • Bubble sort: compare adjacent, swap if out of order, repeat n−1 passes
  • Insertion sort: take next element, insert into correct position in sorted portion
  • Merge sort: divide in half recursively, merge back in sorted order
  • Quick sort: pick pivot, partition into smaller/larger, recurse on each partition
  • Binary search: requires sorted list. Check midpoint, halve search space each time
  • Dijkstra's: find shortest path. Use unvisited table, update distances greedily
  • DFS: uses stack (LIFO). BFS: uses queue (FIFO)

Data Structures

  • Stack: LIFO. Push/pop from top. Uses: recursion call stack, undo, expression evaluation
  • Queue: FIFO. Enqueue at rear, dequeue from front. Uses: scheduling, BFS
  • Linked list: nodes with data + pointer. Insert/delete O(1) if position known, O(n) to find
  • Binary tree: left < root < right. In-order traversal gives sorted output
  • Hash table: key → hash function → index. O(1) average access. Handle collisions (chaining/open addressing)
  • 2D arrays: row-major order. Access time O(1)

Recursion & Programming

  • Recursion needs: base case (stops recursion) + recursive case (calls itself)
  • Each recursive call adds a stack frame — too deep → stack overflow
  • Trace tables: show every variable change for every iteration/step
  • Pseudocode: consistent indentation, clear variable names, loops and conditions
  • Global vs local scope: local vars exist only in their function
  • Parameter passing: by value (copy, original unchanged) vs by reference (original modified)

OOP Concepts

  • Encapsulation: data and methods bundled; private attributes accessed via getters/setters
  • Inheritance: subclass inherits from superclass. Avoids code duplication
  • Polymorphism: same method name, different behaviour in different classes
  • Abstraction: hide implementation detail, expose only what's necessary
  • Class vs object: class is blueprint, object is instance
  • Constructor: special method called on instantiation to initialise attributes

Computational Thinking

  • Decomposition: break problem into smaller sub-problems
  • Abstraction: remove unnecessary detail, focus on what matters
  • Pattern recognition: identify similarities to apply known solutions
  • Algorithm design: express solution as unambiguous step-by-step instructions
  • Backtracking: explore all paths, undo dead ends (e.g. maze solving)
  • Heuristics: approximate solution, good enough when exact is intractable
Exam technique

Every question

  • Read the command word: State (fact only) · Describe (what happens) · Explain (why/how) · Justify (argue with reasoning) · Evaluate (weigh up pros & cons)
  • Apply your answer to the given scenario — generic answers lose marks
  • Trace tables: show EVERY row, EVERY variable change — don't skip steps
  • Pseudocode: any consistent syntax is fine, but be unambiguous
  • Dijkstra's: always show the working table with distances and visited nodes
  • Mark count = expected detail. 4 marks = 4 distinct points
  • SQL queries: check exact syntax — missing semicolons/wrong keywords lose marks
  • Never leave a blank — write a partial attempt for method marks

CPU — FDE cycle
Fetch-Decode-Execute in detail
F
Fetch: PC→MAR (via address bus) · Memory[MAR]→MDR (via data bus) · MDR→CIR · PC incremented
D
Decode: CIR contents decoded by Control Unit — opcode identifies instruction type
E
Execute: ALU performs operation or data moved or branch taken, result stored in ACC or memory
Interrupts: at end of each FDE cycle, CPU checks interrupt register. If set → saves context (registers to stack) → runs ISR → restores context
Registers
PC
Program Counter
Address of next instruction to fetch
ACC
Accumulator
Stores result of ALU operations
MAR
Memory Address Register
Address to read from / write to
MDR
Memory Data Register
Data being transferred to/from memory
CIR
Current Instruction Register
Holds instruction being decoded/executed

Simple, no starvation, poor for short jobs behind long ones

Fair, good for time-sharing. Context switching overhead

Minimises avg wait time. Risk of starvation for long jobs

Translates whole program before running. Fast execution, no source needed at runtime. Error list at end
Interpreter
Translates and runs line by line. Slower. Stops at first error. Good for debugging

Assembly language → machine code. One-to-one translation

Combines object files and library files into executable

⚠ Systems exam traps
FDE detail: name the specific registers involved (PC→MAR, not just "fetched from memory")  ·  Cache vs RAM: explain why cache is faster — it's closer to CPU, not just "smaller"  ·  Virtual memory: causes thrashing when RAM is constantly swapping — say this explicitly  ·  Compiler vs interpreter: compiler = whole program first, interpreter = line by line. Don't mix them up  ·  Pipelining: one instruction per stage simultaneously — not "does multiple things at once" (too vague)
Number representations
Binary & conversions
Binary → Denary: sum of place values (128,64,32,16,8,4,2,1) Denary → Binary: repeated division by 2 Hex → Binary: each hex digit = 4 bits Binary → Hex: group into nibbles
Hex is used as shorthand for binary — easier for humans to read memory addresses
Two's complement (negative numbers)
1
Write positive value in binary
2
Invert all bits (flip 0s and 1s)
3
Add 1 to the result
MSB is the sign bit: 0 = positive, 1 = negative. Range for 8-bit: −128 to +127
Data types & representation
Integer
Whole numbers. Two's complement for signed
Float
Sign · Mantissa · Exponent. Precision vs range trade-off
Character
ASCII: 7-bit, 128 chars. Unicode: up to 32-bit, global chars
Boolean
True/False stored as 1 bit (but often 1 byte in practice)
String
Sequence of characters. Null-terminated in some languages
Compression
Lossy vs Lossless
Lossy
Data permanently removed. Smaller file. Used for images (JPEG), audio (MP3). Cannot recover original
Lossless
All data retained. Recoverable. Used for text, executables, PNG. Run-length encoding, Huffman
Run-Length Encoding (RLE)
AAABBBBBCC → 3A 5B 2C
Effective for data with long runs of repeated values (e.g. bitmap images with large areas of same colour)
Encryption & Hashing
Symmetric encryption
Same key to encrypt and decrypt. Fast. Key distribution problem
Asymmetric encryption
Public key encrypts, private key decrypts. Slower. Solves key distribution
Hashing
One-way function. Same input → same output. Used for passwords, integrity checks. Collisions possible
Digital signature
Hash of message encrypted with sender's private key. Verifies identity and integrity
SQL reference
Key SQL syntax
SELECT field1, field2 FROM table WHERE condition SELECT * FROM students WHERE grade = 'A' ORDER BY surname ASC SELECT s.name, c.title FROM students s JOIN courses c ON s.id = c.student_id INSERT INTO table (col1, col2) VALUES (val1, val2) UPDATE table SET col = val WHERE condition DELETE FROM table WHERE condition SELECT dept, COUNT(*) FROM employees GROUP BY dept HAVING COUNT(*) > 5

⚠ Data exam traps
Two's complement: range is asymmetric — 8-bit: −128 to +127 (not ±127)  ·  Floating point: more bits in mantissa = more precision; more bits in exponent = wider range  ·  Lossy vs lossless: must say whether original can be recovered — not just "data is lost"  ·  SQL WHERE vs HAVING: WHERE is before GROUP BY; HAVING is after  ·  Hashing ≠ encryption: hashing is one-way; encryption is reversible with a key

Protocols compared
TCP vs UDP
TCP
Connection-oriented. 3-way handshake. Guaranteed delivery. Ordered. Error checking. Used for HTTP, email, file transfer
UDP
Connectionless. No guarantee. No ordering. Fast. Used for video streaming, DNS, VoIP, gaming
Packet vs Circuit switching
Packet
Data split into packets, each routed independently, reassembled at destination. Efficient, resilient
Circuit
Dedicated path reserved for duration of call. Consistent quality. Wastes bandwidth if idle (e.g. old phone networks)
Network security
Firewall
Filters packets by IP/port rules. Stateful (tracks connections) or stateless
Encryption
TLS/SSL for HTTPS. Symmetric for speed, asymmetric for key exchange
MAC filtering
Only allow known MAC addresses on network
WPA2/3
WiFi encryption protocols. WPA3 more secure than WPA2
Penetration testing
Authorised simulated attack to find vulnerabilities
Social engineering
Phishing, pretexting — exploits humans not systems
Topologies & hardware
Star
Central switch. Failure of one device doesn't affect others. Expensive (cabling)
Mesh
Every device connected to every other. Resilient, expensive, complex
Bus
Shared backbone cable. Cheap, simple. Single point of failure. Collision domain
Router
Routes packets between networks using IP. Layer 3
Switch
Forwards frames within LAN using MAC table. Layer 2
Hub
Broadcasts to all ports — dumb, causes collisions. Largely obsolete
⚠ Networking exam traps
TCP vs UDP: must say why one is chosen — not just "TCP is reliable". Link to the use case  ·  Router vs switch: router works at Network layer (IP), switch at Data Link layer (MAC)  ·  Packet switching: packets can take different routes and arrive out of order — TCP reorders them  ·  Firewall: doesn't prevent all attacks — social engineering bypasses it entirely

Sorting algorithms compared
At a glance
Bubble sort: Best O(n) · Avg O(n²) · Worst O(n²) · Space O(1) — stable, simple, slow Insertion sort: Best O(n) · Avg O(n²) · Worst O(n²) · Space O(1) — stable, good for nearly-sorted data Merge sort: Best O(n log n) · Avg O(n log n) · Worst O(n log n) · Space O(n) — stable, consistent Quick sort: Best O(n log n) · Avg O(n log n) · Worst O(n²) · Space O(log n) — fast in practice, unstable
Merge sort is preferred when stability matters or worst-case must be guaranteed. Quick sort's worst case is a sorted/reverse-sorted list with bad pivot choice
Searching algorithms
Binary search
1
Requires sorted list — check this first
2
Find midpoint: mid = (low + high) // 2
3
If target = mid → found. If target < mid → search left half. If target > mid → search right half
4
Repeat until found or low > high (not found)
Complexity: O(log n) time · O(1) space (iterative)
Dijkstra's shortest path
1
Set start node distance = 0, all others = ∞
2
Visit unvisited node with smallest tentative distance
3
Update distances to all unvisited neighbours: if current + edge < stored, update
4
Mark current node as visited. Repeat until destination visited
Must show the table in the exam — answer alone gets no marks
Graph traversals
Depth-First Search (DFS)
Uses: Stack (LIFO) Visit node → push unvisited neighbours → pop next → repeat
Goes deep before wide. Good for: finding paths, maze solving, topological sort
Breadth-First Search (BFS)
Uses: Queue (FIFO) Visit node → enqueue unvisited neighbours → dequeue next → repeat
Explores level by level. Finds shortest path in unweighted graphs. Used in: networking, social graphs
Recursion
Structure & call stack
Every recursive function needs: 1. Base case — stops recursion 2. Recursive case — calls itself with simpler input
factorial(n): IF n == 1 THEN RETURN 1 ELSE RETURN n * factorial(n-1)
Each call adds a stack frame (local vars + return address). Too many calls → stack overflow. Tail recursion can be optimised by compiler
⚠ Algorithms exam traps
Binary search on unsorted list: state it requires sorting first — don't just apply it  ·  Dijkstra's table: show every update to every node's distance — the table IS the answer  ·  Big O drop constants: O(2n) = O(n), O(n² + n) = O(n²) — only highest order term matters  ·  Quick sort worst case: O(n²) when pivot is always min or max — e.g. already sorted list  ·  DFS vs BFS: DFS uses stack, BFS uses queue — confused every year
The four pillars
Encapsulation
Bundle data (attributes) and methods together in a class. Mark attributes as private. Access only via public getters/setters. Hides implementation detail.
Inheritance
Subclass inherits attributes and methods from superclass. Adds or overrides behaviour. Avoids code duplication. "is-a" relationship (Dog is-a Animal).
Polymorphism
Same method name, different behaviour in different classes. Achieved through method overriding. e.g. Animal.speak() → Dog.speak() returns "Woof", Cat.speak() returns "Meow".
Abstraction
Hide complex implementation, expose only necessary interface. Abstract classes / interfaces define method signatures without implementation.

ENDPROCEDURE ENDCLASS CLASS Dog INHERITS Animal PUBLIC PROCEDURE speak() OUTPUT "Woof" ENDPROCEDURE ENDCLASS

Boolean algebra laws
Identity
A AND 1 = A
A OR 0 = A
Null/Annihilation
A AND 0 = 0
A OR 1 = 1
Idempotent
A AND A = A
A OR A = A
Complement
A AND NOT A = 0
A OR NOT A = 1
Double negation
NOT(NOT A) = A
Commutative
A AND B = B AND A
A OR B = B OR A
Associative
(A AND B) AND C = A AND (B AND C)
Distributive
A AND (B OR C) = (A AND B) OR (A AND C)
Absorption
A AND (A OR B) = A
A OR (A AND B) = A
De Morgan's laws
The two forms — memorise both
NOT(A AND B) = NOT A OR NOT B NOT(A OR B) = NOT A AND NOT B
Mnemonic: break the bar, change the operator. NOT over a group → distribute NOT, flip AND↔OR
Logic gates
AND
Output 1 only when ALL inputs are 1
OR
Output 1 when ANY input is 1
NOT
Inverts the input
NAND
NOT AND. Output 0 only when ALL inputs 1. Universal gate
NOR
NOT OR. Output 1 only when ALL inputs 0. Universal gate
XOR
Output 1 when inputs DIFFER (exactly one input is 1)
Simplification example
Show every step — marks awarded per step
Simplify: A AND (A OR B) Step 1: Absorption law → A AND (A OR B) = A ✓ Simplify: NOT(NOT A AND NOT B) Step 1: De Morgan's → NOT(NOT A AND NOT B) = NOT(NOT A) OR NOT(NOT B) Step 2: Double negation → A OR B ✓
State the law used at each step — writing just the result loses all working marks
Number systems & conversions
Binary arithmetic
Binary addition: 0+0=0 · 0+1=1 · 1+1=10 · 1+1+1=11 Overflow: result needs more bits than available
Carry the 1 like decimal addition. Overflow flag set when result exceeds bit width
Shifts
Left shift n: multiply by 2ⁿ (fill with 0s on right) Right shift n: divide by 2ⁿ (fill depends on sign) Logical right shift: fill with 0s Arithmetic right shift: fill with sign bit
⚠ Boolean & theory exam traps
Show every Boolean simplification step and name the law — jumping to answer = zero  ·  De Morgan's: NOT(A AND B) = NOT A OR NOT B — the operator FLIPS  ·  NAND/NOR are universal: any logic circuit can be built from only NAND gates (or only NOR gates)  ·  XOR: output is 1 when inputs DIFFER — not "at least one is 1" (that's OR)  ·  Overflow: addition result too large for the bit width — must set overflow flag
